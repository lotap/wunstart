## Setup

- Fresh checkout: run three independent, stateless programs in order — `bun run app-identity my-app` (rename/sync committed identity + static checks), `bun run install-deps` (checkout toolchain + dependencies + hooks), `bun run branch-env` (ports + `.env.local` + containers + branch DB + migrate + final validate-setup gate; pass `--yes` in non-interactive runs). They never import or invoke each other; each fails with the exact earlier command when its prerequisites are missing. Toolchain flags live on `install-deps`: `--pm npm|yarn|pnpm|aube` (Node 22.18+). Lockfiles are tracked; `install-deps` removes other managers' artifacts and repairs a Bun/npm lockfile root name left stale by a rename. There are no saved answers; every run derives its target from explicit flags and current repository/checkout state.
- `app-identity` is the rename path: it synchronizes `package.json`, `wrangler.jsonc`, `src/app-info.ts`, `public/llms.txt`, and the `CONTEXT.md` title, and validates `.env.development` + wasm. It uses Node builtins, so it runs before dependencies. On an existing app, omit the name to keep the current identity (`--yes` for a non-interactive run); pass a new name only for an intentional rename. All three setup phases support `--dry-run`.
- Existing worktree: run `bun run validate-setup` first (standalone health check; also `branch-env`'s final gate; warnings are not failures). Humans re-run it when stuck.
- `bun run dev` (trunk :3000, branches claim 3100-3199 and shift if taken, NEVER `bun --bun` for dev) fails fast without `DEV_PORT` — `branch-env` claims it (branches print it) into `.env.local`, which `dev` loads. `predev` self-provisions deps (`tools/pkg-scripts/install-deps.sh` → `install-deps --yes --quiet`), so pulls/branch switches that change deps repair on next dev start. Hooks via `prepare`; it also runs `effect-tsgo patch` (the tsgo gate needs it for Effect diagnostics — re-run after a fresh install that skipped scripts). `bun run setup:hooks` re-runs only the hook half.
- Wasm kernel (`src/durable-objects/argon2-do-hasher.wasm`) is committed — dev/build/deploy never need Rust; rebuild only after editing `crates/` (see Commands; pre-commit hook blocks `crates/` edits without a staged wasm; params, sharding, rejected alternatives: wunstart skill `references/hashing.md`).
- Postgres: use `bun run branch-env` (it reuses/restarts this worktree's own Postgres first, otherwise uses shared Postgres when credentials work or starts an own stack; a bare `docker compose up -d` uses defaults/ambient `POSTGRES_PORT` and can collide; password `mypassword`). `.env.development` (committed) holds shared dev values (`DATABASE_URL` + JWT `*_SECRETS` + Hyperdrive local string + `VITE_COOKIE_DOMAIN`); `.env.local` (gitignored via `*.local`) holds per-worktree state — `branch-env` owns `DATABASE_URL`, `DEV_PORT`, `MAILPIT_URL`, other keys you add survive. Both are read by the dev server (CF vite plugin) and the `db:*` scripts (`tools/pkg-scripts/drizzle-kit.sh`). File values win over exported environment for dev and `db:*` (`dotenv --override`) — set non-managed overrides in `.env.local`, never by exporting. Exception: `archive-old-activities` honors exported `DATABASE_URL` (and `.env`) — it is the VPS cron entry point, so production keeps working when only the environment points at prod.
- No typecheck script, CI, or product test runner: `bunx tsgo --noEmit` is the type gate (`noUnusedLocals`/`noUnusedParameters` fail the build — no dead bindings); verify with `fmt`, `lint:check`, tsgo, and the dev server. Linter rule tests run via `bun run test:lint` (NEVER `bun --bun` — oxlint RuleTester needs node).
- Teardown when a branch is done: drop its `wunstart_<branch>_<6hex>` database (exact name is in `branch-env`'s plan output; `docker compose exec postgres psql -U postgres -c 'DROP DATABASE "…"'`, or `docker exec` into the owning container), then `docker compose down` — never `-v` when the Postgres container is shared with other worktrees (it deletes this worktree's data volume; on shared storage that is every branch's databases). Then remove the worktree (`git worktree remove <path>`); never touch trunk/main without explicit approval.
- Scratch: `.tmp/` only (never `/tmp`; `bun run clean:tmp` wipes). Chrome-devtools `filePath` resolves from workspace root → use `<worktree>/.tmp/<file>`.

## Commands (`bun --bun run` except setup phases, `dev`, and `test:lint`)

`dev` (trunk :3000; branches serve their claimed port) · `app-identity <name>` (project identity; committed files only) · `install-deps` (checkout deps; `--pm`, `--force`) · `branch-env` (ports + containers + branch DB + migrate + gate; `--yes` for CI/agents) · `validate-setup` (health check) · `build` (vite; committed wasm included) · `build:wasm` (rebuild kernel after Rust edits; commit result) · `setup:hooks` (re-point git at `tools/git-hooks/`) · `test:lint` (linter rule tests — never prefix with `--bun`) · `deploy` · `fmt`/`fmt:check` (oxfmt `src/` + `tools/`) · `lint`/`lint:check` (check passes `--deny-warnings`) · `db:generate`/`db:check`/`db:migrate`/`db:push`/`db:pull`/`db:studio` (+ `db:export`/`db:up`/`db:mcp`/`db:skills` passthroughs) · `cf-typegen` (after `wrangler.jsonc` binding change) · `validate-required-env` (.env shape check; also used by `app-identity` and `validate-setup`) · `dev:email` (:3001) · `build:preview`/`preview` (dev-mode build/serve) · `archive-old-activities` (VPS cron entry; exported `DATABASE_URL` wins, then `.env.local`, then `.env`) · `bunx --bun shadcn@latest add <cmp>` (install shadcn components). Single linter test: `bun run test:lint -- <path>`. No route-generate step: the route tree is emitted by the dev/build server's TanStack Start plugin — restart `dev` when `routeTree.gen.ts` is stale.

Portability: commands above show the bun spelling (committed `bun.lock` default). Under another manager, drop `--bun`/`bunx` (`<pm> run <script>`; script args after `--`, e.g. `npm run branch-env -- --yes`). The checkout's manager is whichever single lockfile exists — exact spellings live in `pmRun`/`phaseCommandWithArgs` (`tools/helpers/package-manager.ts`).

## Hard rules

- DB conventions (factories, free-form labels, Effect Schema only) live in the wunshot skill — backed by its lint rules where those are lintable.
- `no-underscore-dangle` off by design (`_`-prefix marks internal). Route/file placement rules (`_auth-*`, `-components/`) live in the wunstart skill's `references/app.md`.
- Generated files: never hand-edit `routeTree.gen.ts`, `src/components/ui/**`, or `worker-configuration.d.ts`; restart `dev` for the route tree, override UI styles from the caller via `cn()` (narrow patch exception in the wunstart skill's `references/app.md`), and regenerate `worker-configuration.d.ts` with `cf-typegen` after `wrangler.jsonc` binding changes.
- Import via `#/...` — the only alias also registered at runtime (`package.json` `imports`); `@/...` is a tsconfig alias that Vite (`tsconfigPaths`) and Bun happen to resolve, so don't add new ones (`#/` survives any executor and registry porting). Always include `.ts`/`.tsx` extension on relative imports. Blocks grouped packages → `#/` → relative with blank lines; oxfmt sorts within blocks (Tailwind/`cn()` sorting: see wunstart `references/app.md`).
- `// SAFETY:` proof comment above every `as` — lint-enforced (`anti-slop/require-safety-comment-for-type-assertion`).
- Placement: `tools/` holds multi-file programs in own dirs (`setup/app-identity`, `setup/install-deps`, `setup/branch-env`, `linters`, `git-hooks`), executable entries in `tools/pkg-scripts/` (run only via their package script, never imported), plus single-file libraries in `tools/helpers/` (shell + TS — imported, never executed directly). Phase programs never import or invoke each other; they share only neutral leaf helpers. Tools never import from `src/`. `src/scripts/` holds runnable task operations in TS that need the app stack. Sharing rule: a shared `helpers/` module needs multiple consumers; when a check or value crosses the setup-helper boundary, name the consumers on both sides. Second copy extracts: before duplicating a helper into a second file, move it to the shared module instead. Single-consumer values stay with their consumer (a catch-all `defaults` module re-collects them).
- TS entry points run through `tools/pkg-scripts/run-ts.sh` (bun, nub, or node 22.18+), so the setup phases work before dependencies exist.
- Formatting: oxfmt auto-sorts imports and Tailwind — don't hand-order. Run `fmt` after editing `src/` or `tools/` (style tokens live in `.oxfmtrc.json`).
- House voice (not linted): `/** */` doc comments + `{@link}` cross-refs; sentence case + curly apostrophes (`’`, not `'`) in user copy. Model/ops comment voice: wunshot skill.
- Custom lint plugins (`wunstart`, `wunshot`, `anti-slop*` in `oxlint.config.ts`) are the backstop — the skills are the spec. Before commit: `fmt`, then `lint:check` + `bunx tsgo --noEmit` clean.
- Commit only on explicit request — except the initial commit of a newly created project, which is part of setup: make it once the app verifies, and never push without permission.
- Environment is read-only without explicit permission: NEVER install packages/tools (bun, npm, pip, brew, apt, etc.) or otherwise modify anything outside the repo. Propose exact names/commands and wait for approval — user-site installs count.
- Kill dev by PID only: `lsof -ti :<port> -sTCP:LISTEN | head -1 | xargs kill` (trunk :3000; branches print their claimed port at the end of `bun run branch-env`).

## Deliberation

Load-bearing: each rule below was added after a concrete agent failure. Do not trim as generic advice.

- Never invoke cost, risk, or churn to defend the status quo. A cost objection must be a verifiable claim — what breaks, who pays, how much (a grep count, a timeboxed attempt) — never an adjective ("big churn", "risky"). Decide the right shape on merits first; cost is weighed after, never recruited to justify a decision already made.
- While work is uncommitted, churn cost is zero: no diff exists, no reviewer has seen it, nothing can conflict. If churn is the only objection to an improvement, make the improvement — don't debate it.
- Think merits-first, conclude last: lay out the evidence and the alternatives before the verdict. A reason that shows up after the conclusion is suspect — remove it and check whether the conclusion still stands. This is the mechanism that breaks the rules above: a decision already made recruits cost, risk, and churn as its defense.
- When a task admits multiple reasonable approaches — or you're unsure it doesn't — propose before implementing. This matters most while work is fresh or uncommitted: an early implementation anchors all later thinking, and that anchoring cost dwarfs the cost of rebuilding.
- When revising your own work, review it as an adversary: re-read the whole artifact, not just the diff; test each part by removing it; argue against keeping it, never for keeping it.
- Prefer a small structural change now over an expensive retrofit later: policy by construction beats per-site discipline. Uncommitted churn is free (above), but deferred structure is debt — build the shape now.
- Settle readability debates by rule, not taste: flat over nested — guard clauses over ternaries, small named helpers over clever dispatch. Don't relitigate settled style per site.

## Tone

- Plain English by default: write like explaining to a smart friend — cut preamble, hedging, and consultant-speak; take whatever length real clarity needs. Facts survive verbatim (paths, commands, filenames, numbers, decisions stay exact): simplify around them, never them. No ceremony unless the content genuinely has parts; light personality welcome, meme never.
